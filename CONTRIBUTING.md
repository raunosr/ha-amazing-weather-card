# Contributing

Use Node.js 24 and `npm ci`. Run `npm run dev` for the credential-free fixture demo on port 5278. Source modules separate HA data access, conversion, astronomy, chart rendering, the card and the editor.

Before a pull request:

```sh
npm run format
npm run check
npx playwright install chromium
npm run test:browser
```

Commit the rebuilt `dist/ha-amazing-weather-card.js` whenever source or dependency changes affect it. CI verifies that the committed bundle matches a fresh build. Screenshots are demonstration data generated by the browser tests, not personal HA data.

Add meaningful tests for data transformations and behaviour changes. Preserve missing-value semantics, source attribution and provider periods. Do not add credentials, private entity attributes or real location screenshots to fixtures. Report problems through GitHub Issues with steps to reproduce, a sanitized config, HA/card/browser versions and the weather provider.

## Releasing

1. Update `package.json`, the lockfile version and `CHANGELOG.md`.
2. Format, run the checks, rebuild and commit. Confirm CI and HACS validation succeed.
3. Run the **Release** workflow from the default branch, supplying the existing package version (for example `0.1.0`).
4. The workflow verifies and builds the checked-out commit, creates `v<version>` and attaches the standalone JavaScript file and its SHA-256 checksum. It refuses an existing release.
5. HACS installs from the tagged repository's `dist` folder or the matching release asset. Run HACS validation again if needed to check the release.

No npm package publication is needed; `private: true` intentionally prevents it.
